它是什么

远程代码面试需要把三样东西放在一起：共享的编辑器、能运行代码的地方、题目。CodeEditor 把它们放在同一个页面里。点一下就创建一个房间，拿到链接的人都能进来；不用安装任何东西，也不需要注册。

  • 共享编辑器：能看到对方的光标和选区；撤销只撤销自己的修改。
  • 运行：服务器编译并运行代码，把输出、CPU 时间和内存峰值发给房间里的所有人。
  • 题目面板支持 Markdown，可以从内置题库或面试官自己保存的题目里选一道发到房间。
  • 共享计时器、深浅两套主题，以及手机上的布局。

让两个编辑器保持一致

最初的版本每敲一个键就把整份文本发出去。这样做很简单，但只要两个人同时打字就会出错：后到的消息覆盖先到的，对方的光标也会跳走。现在的版本用的是操作变换（OT）。

按键
→
操作保留 / 插入 / 删除，基于修订 n
→
服务器变换把 n 之后已接受的操作考虑进去
→
广播 + 确认
→
其他编辑器应用光标位置不变
  • 同一时刻只有一个操作在途。浏览器等待一个操作的确认，其间的修改合并进缓冲；服务器发来的操作先对这两者做变换，再作用到编辑器上。
  • 撤销也要变换。撤销栈里存的是逆操作，别人的每个操作都会变换进去，所以 Ctrl+Z 不会删掉对方写的内容。
  • 断线重连。服务器保留最近的修订历史，重连的客户端只收到自己错过的部分。如果服务器在此期间重启过，客户端以最后一次确认的文本为共同祖先做三方合并。
  • 两份实现，一种行为。服务端是 Python，浏览器端是 JavaScript。两边都按 UTF-16 码元计数，所以 emoji 不会让位置错位。

运行别人写的代码

访客输入什么，网站就运行什么。每次运行都经过一个独立的小启动器进程：

  • 独立的、用完即删的目录，干净的环境变量；
  • 限制 CPU 时间、地址空间、文件大小和打开文件数，外加墙上时钟超时，超时后杀掉整个进程组；
  • 输出写到有大小上限的文件里，输出洪水既不会拖住也不会撑爆服务进程；
  • 服务以 root 运行时：每个并发的运行使用各自的非特权用户，限制进程数，并进入一个空的网络命名空间。
这是加固，不是容器：程序仍然可以读取主机上所有用户可读的文件。README 里写明了这一点；另有一个管理命令会实际运行死循环、内存炸弹、fork 炸弹和联网探针，显示当前机器上哪些保护真正生效。

题库与判题

内置 29 道题，每道题有题面、示例、隐藏测试和参考解。期望输出是在导入题目时运行参考解得到的，所以题面、测试和解答不会互相走样。提交的代码只编译一次，然后逐个用例运行；页面给出每个用例的结果，只有示例用例会显示输入和输出。

怎么验证它是对的

  • 交叉校验 OT。Python 和 JavaScript 两份实现拿到同一批随机操作，结果必须完全一致。
  • 客户端模拟器。多个模拟的浏览器随机编辑，消息乱序到达，连接随机断开又恢复，用户随机撤销；最后每个客户端的文本必须和服务器完全一致。故意改坏的代码变体会被它抓住。
  • 每道题的参考解都真的被判一遍，这是测试的一部分。
  • 沙箱的 root 路径（切换用户、断网、清理）在一次性容器里以 root 身份实际运行。

设计笔记

  • 发送变化，而不是整份文档。整份同步经不起两个人同时打字；可以互相变换的小操作可以。
  • 要测的是子进程，不是服务进程。fork 出来的子进程一开始带着父进程全部页面的副本，从 Web 进程这一侧读到的内存其实是 Web 进程自己的。启动器会再 fork 一次，只报告那个程序本身的用量。
  • 清理和运行一样需要测试。一个创建上千层嵌套目录的程序不应该能让后面的运行全部卡住；这有专门的测试。
