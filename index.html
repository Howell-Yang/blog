I take deep-learning models from training to production automotive chips. At QCraft I lead model quantization and on-device deployment for about 19 production driving and parking models: BEV perception, occupancy, vector maps, temporal tracking and end-to-end planning. They run on Horizon J5/J6M, NVIDIA Orin, Qualcomm and AXERA chips.

My work spans quantization algorithms (PTQ, QAT, quantization-aware distillation), bit-level numerical consistency across toolchains, latency modeling, and the platforms and release gates that make this repeatable. I lead a six-engineer team and am technical lead for bringing our urban NOA stack to a new chip family. Before QCraft I worked at Tencent Maps and Yitu Technology, and I studied pattern recognition at Beihang University.

QCraft 轻舟智航

Oct 2022 – present

Model Quantization & Deployment Lead, Perception ML-Infra

Joined as Machine Learning Infrastructure Engineer; promoted to L5 in 2024; team lead since 2025.

Team leadership and program delivery

  • Lead a 6-engineer quantization and deployment team (dotted-line from 2025, direct reports from 2026): quarterly goals, P0/P1 priorities, an owner and a backup for each of about 19 production models, design reviews and 1:1 coaching.
  • Technical lead since June 2026 for the AXERA chip program (M97 700-TOPS demo board, then the M95 350-TOPS target): staged bring-up, model adaptation and quantization, road-test issue triage. The urban NOA v4 stack runs on test vehicles with no frame drops on key models.
  • Launched AI-assisted automation (60 person-days, Apr–Jun 2026): a Feishu bot and coding-agent skills adapt new model features for quantization. Also ran a training-speedup push across five models; one model trained about 50% faster.
  • Built the team's bench: mentoring to independent model ownership, monthly quantization sessions, a company-wide tech talk and a 33-page knowledge base. Model owners have started running auto-QAT releases themselves.

Quantization algorithms

  • Moved the method forward with each model generation: scale-search PTQ (2023, patent filed), LSQ-based AutoQuant for MapFormer and SparseTrack (2024), distillation-based QAT (2025), and large-scale quantization-aware distillation (QAD) for end-to-end trajectory outputs (2026).
  • Cut quantization loss from about 2 points (PTQ) to about 0.5 points (QAT) on five production perception models.
  • Changed the production goal from average-metric parity to case-level consistency with the float model (an AEB target must not be detected even a frame late), supported by per-layer, cumulative-error and W16A16 sensitivity tools.
  • Designed adaptive lookup tables for non-linear operators: across 600 LUT modules in four production graphs, 0.217 LSB mean error (2 LSB max) with 85% fewer tables than the fixed 126-table design.
  • Quantized the end-to-end World2Action planning model through controlled single-variable experiments (25 key metrics, 388 shared scalars); quantized versions went to on-vehicle testing.

Toolchain and deployment platform

  • Built QNN Web, a one-click conversion service for NVIDIA Orin and Horizon J5/J6 (gRPC back end, configs generated from ONNX, TensorRT timing cache): 4,273 production conversions, build time from 30–60 to about 5 minutes, about 80% less manual effort. Later added database-backed jobs, queueing and MCP endpoints for AI agents.
  • Defined the quantization framework's standard stages (pre-export, data conversion, Horizon export, post-processing, per-stage unit tests); led Horizon toolchain upgrades and worked with Horizon Robotics on toolchain issues.
  • Led the team onto new targets: Qualcomm (model splitting and latency tuning), TensorRT QDQ INT8, and VLM quantization on Horizon J6P.

Numerical correctness and release quality

  • Built a layered consistency method that isolates errors stage by stage across float, QAT, in-house IR, LibTorch, Horizon HBIR/HBM and on-board post-processing; it found an rsqrt LUT split-point error, an upsample align_corners mismatch and pose-precision bugs.
  • Introduced evidence-graded release gates (source, build, simulation, board, vehicle), default-off feature flags and a regression set of past failures run before every release.

Latency, training infrastructure and model architecture

  • Built a structural latency model accurate to 0.7% on board (19.38 ms predicted vs 19.25 ms measured), which ruled out a wider occupancy range at 10 Hz before any code was written.
  • Wrote the OneModel phase-2 plan: one shared image backbone and neck for five perception models across 9 cameras, estimated to save 5–9 ms per frame, with PCA on existing checkpoints to size the backbone.
  • Migrated BEV occupancy training to PyTorch 2.x: 54% faster per iteration (V100, batch 16, AMP), 9% less GPU memory, scaling benchmarked to 112 GPUs.
  • Designed and reviewed a ~235M-parameter SparseDrive-style end-to-end driving prototype (10 cameras, LiDAR and SD map feeding detection, map, occupancy, traffic-light and planning heads).
